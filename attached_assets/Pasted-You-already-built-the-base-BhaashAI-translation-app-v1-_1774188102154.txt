### FEATURE 1 — Live Mic → Real-Time Transcription (STT via WebSocket)

Use Sarvam's WebSocket Streaming STT endpoint:
wss://api.sarvam.ai/speech-to-text-translate/streaming

Model: saaras:v3 (do NOT use saarika — it's being deprecated)
Audio format: PCM raw, 16kHz, mono, 16-bit little-endian
Auth header on WS connect: { "api-subscription-key": "<USER_API_KEY>" }

### WebSocket Init Config (send as first message after connect):
```json
{
  "type": "config",
  "data": {
    "sample_rate": 16000,
    "encoding": "pcm_s16le",
    "model": "saaras:v3",
    "language_code": "unknown",
    "mode": "transcribe",
    "vad_signals": true,
    "high_vad_sensitivity": false
  }
}
```

### Live Audio Pipeline (React Native):
1. Use `expo-av` or `react-native-audio-record` to capture raw PCM audio
2. Capture in 100ms chunks → convert to base64 → send to WebSocket as:
   { "type": "audio", "data": "<base64_pcm_chunk>" }
3. Receive partial + final transcripts from server:
   - { "type": "partial_transcript", "transcript": "..." } → show in gray italics
   - { "type": "final_transcript", "transcript": "..." } → show in full black text
4. On "final_transcript" → immediately pipe the text into callSarvamTranslate()
5. Show translation in output card LIVE as user speaks

### VAD Events to handle:
- { "type": "vad_speech_start" } → show pulsing mic animation
- { "type": "vad_speech_end" } → show "Processing..." state
- { "type": "end_of_utterance" } → finalize and send flush signal

### Send flush signal to force finalize:
{ "type": "flush" }

### Send end signal when stopping:
{ "type": "end" }

### FEATURE 2 — Speak Output (TTS via REST then WebSocket)

#### TTS REST API (for translated text up to 500 chars):
POST https://api.sarvam.ai/text-to-speech
Headers: { "api-subscription-key": "<API_KEY>", "Content-Type": "application/json" }

Body:
```json
{
  "inputs": ["<translated_text>"],
  "target_language_code": "<target_lang_code>",
  "speaker": "meera",
  "model": "bulbul:v3",
  "pitch": 0,
  "pace": 1.0,
  "loudness": 1.5,
  "speech_sample_rate": 22050,
  "enable_preprocessing": true,
  "eng_interpolation_wt": 123
}
```
Response: { "audios": ["<base64_wav>"] }
→ Decode base64 → play with expo-av Audio.Sound

#### TTS WebSocket (for long text >500 chars or streaming voice agents):
wss://api.sarvam.ai/text-to-speech/streaming

Send config first:
```json
{
  "type": "config",
  "data": {
    "target_language_code": "<lang>",
    "speaker": "meera",
    "model": "bulbul:v3",
    "min_buffer_size": 150
  }
}
```
Then send: { "type": "text", "data": "<chunk of text>" }
Receive: base64 audio chunks → buffer → play progressively with expo-av

New screen: /conversation (accessible from Voice tab toggle)

Layout — split vertically:
- TOP HALF (Speaker A):
  - Language label: e.g., "हिंदी (Hindi)"
  - Bubble feed: Speaker A's speech transcripts + translations
  - MIC BUTTON A (tap and hold to speak, release to finalize)
  
- BOTTOM HALF (Speaker B, visually flipped 180°):
  - Language label: e.g., "தமிழ் (Tamil)"
  - Bubble feed: Speaker B's speech transcripts + translations
  - MIC BUTTON B

### Conversation Flow:
1. A taps mic → WebSocket STT opens → A speaks in Language A
2. Transcript fires → callSarvamTranslate(transcript, sourceA, targetB) → B sees translation
3. TTS plays translated text aloud in Language B's voice
4. B taps their mic → same reverse process

### Bubble UI:
- Speaker A bubbles: right-aligned, saffron (#FF6B00) background
- Speaker B bubbles: left-aligned, deep navy background
- Each bubble shows: [original text] + [translated text in smaller italic below]
- Timestamp on each bubble

### FEATURE 9 — Production Error Handling (complete all gaps)

Handle ALL these states gracefully:

| Scenario | UX Response |
|---|---|
| WebSocket STT drops mid-speech | Auto-reconnect once, show "Reconnecting..." |
| TTS audio decode fails | Toast "Playback failed, try again" |
| Translation returns empty string | Show "Translation unavailable" in output |
| Mic permission denied | Full-screen modal: "Microphone access needed" + link to settings |
| Device has no mic | Hide Voice tab entirely, show info toast |
| API key invalid (401) | Banner: "Invalid API key — update in Settings" |
| Network offline | Show offline banner + disable all API buttons |
| Text input > 1000 chars | Truncate at 1000 with "Text too long" warning |
