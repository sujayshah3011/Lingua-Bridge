- React + Vite (existing)

- **Language**: TypeScript (strict mode, no `any`)

- **Database**: Supabase PostgreSQL via `@supabase/supabase-js` (server-side client with service role key)

- **Validation**: Zod on ALL inputs (request body, query params, route params)
- **Environment**: dotenv — never commit secrets, always use `.env`

### Admin Panel
- Same Vite project, under `/admin` route
- Protected by Supabase Auth + role check (`profiles.role = 'admin'`)
- Separate layout component, shared design tokens with main site

## SUPABASE SETUP INSTRUCTIONS

### Tables to create (provide SQL migration files)

```sql
-- profiles (extends Supabase auth.users)
CREATE TABLE profiles (
  id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  full_name TEXT,
  role TEXT NOT NULL DEFAULT 'user' CHECK (role IN ('user', 'admin')),
  avatar_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- categories
CREATE TABLE categories (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL,
  parent_id UUID REFERENCES categories(id),
  image_url TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- products
CREATE TABLE products (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL,
  description TEXT,
  price NUMERIC(10,2) NOT NULL,
  compare_price NUMERIC(10,2),
  category_id UUID REFERENCES categories(id),
  tags TEXT[],
  stock INTEGER DEFAULT 0,
  sku TEXT UNIQUE,
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- product_images
CREATE TABLE product_images (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  product_id UUID REFERENCES products(id) ON DELETE CASCADE,
  url TEXT NOT NULL,
  is_primary BOOLEAN DEFAULT FALSE,
  sort_order INTEGER DEFAULT 0
);

-- carts
CREATE TABLE carts (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  product_id UUID REFERENCES products(id) ON DELETE CASCADE,
  quantity INTEGER NOT NULL DEFAULT 1,
  variant JSONB, -- { size, color } for Phase 2
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, product_id)
);

-- wishlists
CREATE TABLE wishlists (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  product_id UUID REFERENCES products(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, product_id)
);

-- orders (Phase 1 — no payment)
CREATE TABLE orders (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  items JSONB NOT NULL, -- snapshot of cart at time of order
  total_amount NUMERIC(10,2) NOT NULL,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending','processing','shipped','delivered','cancelled')),
  shipping_address JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Row Level Security (RLS) — enable on ALL tables
```sql
-- profiles: users read/update own row; admins read all
-- products: public read; service role write
-- carts: users access only their own rows
-- wishlists: users access only their own rows
-- orders: users see own; admins see all
-- (provide full RLS policy SQL for every table)
```

### Supabase Storage
- Create a bucket: `product-images` (public read, authenticated write)
- Create a bucket: `avatars` (public read, authenticated write)

### Supabase Auth config
- Enable email/password provider
- Set up `handle_new_user` trigger to auto-insert into `profiles` on signup:
```sql
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO profiles (id, full_name)
  VALUES (NEW.id, NEW.raw_user_meta_data->>'full_name');
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();
```

## BACKEND API ROUTES

### Auth (thin layer — Supabase handles actual auth)
```
POST   /api/auth/profile          Update display name / avatar
GET    /api/auth/me               Return profile + role from profiles table
```
> Note: Login/signup/logout are handled directly by Supabase JS client on the frontend.
> The backend only needs to verify the JWT and expose profile data.

### Products
```
GET    /api/products              Public. Filters: ?category=&minPrice=&maxPrice=&sort=&search=&page=&limit=
GET    /api/products/:slug        Public. Returns product + images
POST   /api/products              Admin only. Body: Zod-validated product fields
PUT    /api/products/:id          Admin only
DELETE /api/products/:id          Admin only (soft delete: is_active = false)
POST   /api/products/:id/images   Admin only. Upload to Supabase Storage, insert into product_images
DELETE /api/products/:id/images/:imageId  Admin only
```

### Categories
```
GET    /api/categories            Public. Returns tree structure (parent + children)
POST   /api/categories            Admin only
PUT    /api/categories/:id        Admin only
DELETE /api/categories/:id        Admin only (only if no products linked)
```

### Cart
```
GET    /api/cart                  Auth required. Returns cart items with product details joined
POST   /api/cart/add              { productId, quantity }
PUT    /api/cart/update           { productId, quantity }
DELETE /api/cart/remove/:productId
DELETE /api/cart/clear
```

### Wishlist
```
GET    /api/wishlist              Auth required
POST   /api/wishlist/add          { productId }
DELETE /api/wishlist/remove/:productId
```

### Orders
```
POST   /api/orders                Auth required. Snapshot cart → create order → clear cart
GET    /api/orders                Auth: user sees own | Admin: all orders
GET    /api/orders/:id            Auth required + ownership check
PATCH  /api/orders/:id/status     Admin only. { status: 'processing'|'shipped'|'delivered'|'cancelled' }
```

### Admin
```
GET    /api/admin/dashboard       Stats: product count, order count, user count, pending orders count
GET    /api/admin/users           Paginated user list with role
PATCH  /api/admin/users/:id/role  { role: 'user'|'admin' }
```

## MIDDLEWARE CHAIN (apply in this order)

```typescript
// verifySupabaseJWT.ts
// 1. Extract Bearer token from Authorization header
// 2. Call supabase.auth.getUser(token) — never decode JWT manually
// 3. Attach req.user = { id, email, role } (role fetched from profiles table)
// 4. Return 401 if invalid/expired

// requireAdmin.ts
// 1. Must run AFTER verifySupabaseJWT
// 2. Check req.user.role === 'admin'
// 3. Return 403 if not admin

// rateLimiter.ts
// Auth routes: 10 requests per 15 minutes per IP
// API routes: 100 requests per 15 minutes per IP

// errorHandler.ts (global, last middleware)
// Catch all thrown errors
// Zod errors → 400 with field-level messages
// Supabase errors → map to appropriate HTTP codes
// Unknown errors → 500, never expose stack trace in production
```

## FRONTEND AXIOS INTERCEPTOR

```typescript
// src/lib/axiosClient.ts
// 1. Create axios instance with baseURL from env
// 2. Request interceptor: get current Supabase session, attach Bearer token
// 3. Response interceptor: on 401, call supabase.auth.refreshSession(), retry once
// 4. On second 401: sign out user, redirect to /login
```

## FRONTEND AUTH FLOW

```
App loads
  → check supabase.auth.getSession()
  → if session exists: fetch /api/auth/me → store user + role in Zustand authStore
  → if role === 'admin': unlock /admin routes
  → if no session: user is guest (cart uses localStorage until login, then merge)

Login (Supabase client directly):
  → supabase.auth.signInWithPassword()
  → on success: fetch /api/auth/me → update store
  → redirect to previous page or homepage

Logout:
  → supabase.auth.signOut()
  → clear Zustand store
  → redirect to /
```
